# suno

`suno` создаёт песни и инструменталы, редактирует готовые треки и экспортирует результат в разные форматы. Операция выбирается через `action`.

## Пример генерации

```jsonc
{
  "bot": "{{BOT_USERNAME_TEXT}}", // обязательно: username бота.
  "token": "[Ваш API-токен]", // обязательно: API-токен бота.
  "user": "{{USER_ID_TEXT}}", // обязательно: ID пользователя.
  "model": "suno", // обязательно: ключ Suno.
  "action": "generate", // обязательно: создать песню.
  "mv": "chirp-v5-5", // необязательно: версия Suno.
  "prompt": "{{suno_prompt}}", // обязательно: идея, стиль или инструкция; не текст песни.
  "custom": false, // необязательно: true для своего текста и стиля.
  "instrumental": false, // необязательно: true для трека без вокала.
  "send_answer": true // необязательно: отправить результат в чат.
}
```

Для режима `custom=true` используйте две разные переменные: `prompt` — описание результата, а `lyrics` — готовый текст песни. Не подставляйте одну и ту же переменную в оба поля.

```jsonc
{
  "model": "suno",
  "action": "generate",
  "prompt": "{{suno_prompt}}", // описание песни или инструкция.
  "lyrics": "{{suno_lyrics}}", // отдельная переменная с текстом песни.
  "custom": true,
  "tags": "indie pop, warm vocal"
}
```

## Загрузка трека и переменная Music ID

Если пользователь отправляет файл через стандартную **Форму ввода** PuzzleBot, получать прямую Telegram-ссылку вручную не нужно. Форма сохраняет `file_id`, а трекер сам скачивает файл через PuzzleBot и передаёт Suno уже готовую публичную ссылку.

1. В PuzzleBot откройте раздел **Переменные** и создайте две персональные текстовые переменные:
   - `suno_audio_file` — для файла из формы ввода;
   - `suno_music_id` — для ID, который вернёт Suno.
2. В команде, принимающей файл, добавьте **Форму ввода**:
   - тип ввода — **Отправка сообщения**;
   - маска ввода — **Аудио** (при необходимости также **Голосовая запись**);
   - переменная — `{{suno_audio_file}}`.
3. После формы запустите команду с запросом к трекеру. В запросе передайте `"file_id": "{{suno_audio_file}}"`. Значение этой переменной — Telegram `file_id`, а не URL.
4. Передайте имя второй переменной в `music_id_variable`. После успешной загрузки трекер запишет в неё ID трека.

```jsonc
{
  "bot": "{{BOT_USERNAME_TEXT}}",
  "token": "[Ваш API-токен]",
  "user": "{{USER_ID_TEXT}}",
  "model": "suno",
  "action": "upload",
  "file_id": "{{suno_audio_file}}", // Telegram file_id из стандартной формы ввода PuzzleBot.
  "music_id_variable": "suno_music_id", // имя переменной без фигурных скобок.
  "send_answer": false
}
```

Поле `token` должно содержать токен **Входящих запросов** того же бота PuzzleBot, который получил файл. Трекер сам обработает `file_id` и подготовит аудио для загрузки — никаких дополнительных ссылок или токенов в сценарий добавлять не нужно. Файл уходит в Suno в исходном виде, без перекодирования.

Если файл уже лежит по доступной без авторизации ссылке, форму и `file_id` можно не использовать: передайте эту ссылку в `audio_url`.

После завершения используйте `"music_id": "{{suno_music_id}}"` в `extend`, `cover`, `stems` и других операциях. Если `send_answer=false`, сообщение с результатом в чат не отправляется, но переменная с ID заполняется.

Для `cover` и `extend` отдельная загрузка не обязательна: в этих операциях можно сразу передать `audio_url` или `file_id`. Отдельный `upload` нужен, когда один и тот же трек используется в нескольких операциях подряд.

### Куда попадает ID трека

- В `music_id_variable` передавайте **имя** переменной, а не её значение: `"music_id_variable": "suno_music_id"`, а не `"{{suno_music_id}}"`. Имя пишется латиницей, цифрами и подчёркиванием, до 64 символов.
- Если в поле подставилось значение (например, ID вместо имени), трекер не создаёт переменную со случайным именем, а записывает ID в `suno_music_id`.
- Если поле не передано, ID результата операций редактирования и экспорта тоже уходит в `suno_music_id`. Для обычной генерации (`action: generate`) имя переменной указывайте явно.
- Suno возвращает на один запрос несколько вариантов трека. Первый ID попадает в основную переменную, остальные — в `<имя>_2`, `<имя>_3` и `<имя>_4`. Например, при `music_id_variable: suno_music_id` второй вариант окажется в `suno_music_id_2`, и его можно отдельно продлить или выгрузить в WAV.
- Переменные создавайте заранее: трекер их не создаёт. Если переменной у бота нет, запись пропускается без ошибки, поэтому заводить `_2`, `_3` и `_4` нужно только под те варианты, которые реально используются в сценарии.

## Основные параметры

| Ключ | Значение | Описание |
| --- | --- | --- |
| `model` | `suno` | Модель Suno. |
| `action` | значение из таблицы | Выбранная операция. |
| `mv` | например `chirp-v5-5` | Версия Suno. |
| `prompt` | текст или переменная | Идея, стиль или инструкция для результата. |
| `lyrics` | текст или переменная | Отдельный готовый текст песни для `custom=true`. |
| `music_id` | ID готового трека | Нужен для большинства операций редактирования. В `cover` и `extend` вместо ID можно передать ссылку на аудио. |
| `music_id_variable` | имя переменной PuzzleBot | Куда записать ID результата. Переменная должна существовать заранее. |
| `custom` | `true` / `false` | Использовать свой текст и стиль. |
| `instrumental` | `true` / `false` | Создать трек без вокала. |
| `title` | текст | Название результата. |
| `tags` | стили через запятую | Жанр, настроение и звучание. |
| `negative_tags` | стили через запятую | Что исключить из звучания. |
| `vocal_gender` | `male` / `female` | Пол вокала. |
| `style_weight` | число от 0 до 1 | Насколько строго держаться стиля из `tags`. |
| `audio_weight` | число от 0 до 1 | Насколько близко держаться исходного аудио. |
| `weirdness_constraint` | число от 0 до 1 | Вариативность результата; алиас — `weirdness`. |
| `continue_at` | секунда | С какого момента продолжать трек в `extend`. |
| `stem_type` | например `vocals` | Нужная дорожка для `stems`. |
| `file_id` | Telegram file_id | Файл из стандартной формы ввода PuzzleBot. Трекер сам скачает его и получит публичный URL; подходит для `upload`, `cover` и `extend`. |
| `audio_url` | URL файла | Прямая публичная ссылка на исходное или референс-аудио. |
| `name` | текст | Имя создаваемого голоса для операции `create_voice`. |

Поля, которые не относятся к выбранной операции, добавлять не нужно.

### Регистр полей

Поля трекера читаются без учёта регистра: `Instrumental` и `instrumental` — одно и то же поле. Правило общее для всех полей запроса, поэтому заглавная буква из настроек PuzzleBot больше не приводит к тому, что значение теряется и вместо него применяется настройка бота. Если в запросе есть оба варианта написания, побеждает тот, который записан точно как в документации.

Логические поля принимают `true` / `false`, `1` / `0`, `yes` / `no` и `on` / `off` — регистр значения тоже не важен, поэтому строка `True` из PuzzleBot читается корректно.

### Тонкая настройка звучания

`style_weight`, `audio_weight` и `weirdness_constraint` принимают значения от 0 до 1; если поле не передано, используется 0.5. Ноль передаётся именно как ноль, а не как «значение не задано»: `weirdness_constraint: 0` даёт максимально предсказуемый результат. У `weirdness_constraint` есть короткий алиас `weirdness`.

```jsonc
{
  "model": "suno",
  "action": "generate",
  "prompt": "{{suno_prompt}}",
  "tags": "synthwave, night drive", // стиль и настроение.
  "negative_tags": "noise, clipping", // что исключить.
  "vocal_gender": "female", // пол вокала.
  "style_weight": 1, // строго держаться стиля из tags.
  "audio_weight": 0.5, // близость к исходному аудио.
  "weirdness": 0 // без экспериментов.
}
```

`vocal_gender` принимает `male` и `female` (а также `мужской` и `женский`). В кастомном режиме пол вокала дополнительно закрепляется стилевым тегом, потому что одного поля Suno не всегда достаточно.

### Инструментал

- `instrumental: true` работает в генерации, кавере и продлении: продолжение инструментального трека больше не приходит с вокалом.
- В кастомном режиме (`custom: true`) вместе с `instrumental: true` текст песни не нужен: описание из `prompt` уходит в стиль, а не в слова.
- Операции `add_instrumental` и `add_stem` этот флаг не поддерживают — не добавляйте его в такие запросы.

## Несколько операций в одном сценарии

- `action: upload` не занимает слот медленного режима. Сценарии вида «загрузить трек → `add_stem`» или «загрузить трек → `extend`» можно отправлять двумя запросами подряд: второй не отобьётся сообщением о том, что предыдущая генерация ещё выполняется. Сами генерации (`generate`, `cover`, `extend`, `add_stem`) слот занимают по-прежнему.
- При `send_answer: false` служебная загрузка проходит тихо: без статуса «печатает», без сообщения о принятом запросе и без реакции на сообщение. Переменная с ID при этом заполняется.
- Аудио, пришедшее в команде с музыкальной моделью, не расшифровывается в текст, даже если в боте включено распознавание голосовых сообщений. Файл уходит в Suno.

## Ответ

Задача выполняется в фоне. Готовый ответ содержит ссылку на аудио и ID трека для следующих операций. Чтобы сохранить ID отдельно, заранее создайте переменную PuzzleBot и передайте её имя в `music_id_variable`.

Как результат приходит в чат:

- Треки в MP3, M4A, MP4 и AAC — аудиоплеером.
- WAV и остальные форматы — файлом-вложением. Это касается и экспорта `action: wav`: плеер такие файлы не принимает, поэтому они сразу уходят документом.
- Если мессенджер не забрал файл (например, из-за размера), в чат придёт ссылка на скачивание, чтобы готовый результат не потерялся.
